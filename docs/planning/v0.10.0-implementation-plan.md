# v0.10.0 implementation and acceptance map

Baseline: published v0.9.0 / `fe97915`. Scope: U06–U08 and incremental U10.
Status: implementation and release acceptance complete. All 194 outputs, runtime/SDK/package checks
and frozen player targets have retained evidence. Known unsupported playback paths have explicit
preflight rejection; Shaka percentage-line layout and WebVTT syntax validation are fixed. No publication.
See [acceptance](../release-0.10.0.md) and [machine evidence](../release-0.10.0-evidence.json).

| Phase | Implementation | Acceptance |
| --- | --- | --- |
| P0 | Additive track IDs, selection, metadata and reports; fixed input sets | Legacy literals/exhaustive matches; output format probes |
| P1 | Shared continuous scheduler for N selected audio inputs | Independent EOF/tails, offsets, ranges, epochs, aggregate budgets |
| P2 | Production ID3/ADTS Packed AAC with shared resource/sample crypto | Exact clocks/wrap, malformed input, clear/AES-128/SAMPLE-AES |
| P3 | Bounded continuous wvtt cue mux and classic finalization | Overlap, gaps, late clipping/rejection, epochs/split, settings |
| P4 | Combination queries, docs, examples and runtime/SDK evidence | Native/Node WASM/Chrome, independent media validation and player evidence |

Late cues never stall media or rewrite sealed fragments. Fully late cues are
rejected with a receipt; partially late cues are clipped and reported. Unsupported
STYLE/REGION/non-text profiles are rejected. Shaka extraction-adapter evidence is
separate from direct mixed-file playback. Unverified backend/player profiles must
not be advertised as supported.

Keep the hls-transmux name, old with_audio replacement semantics and schema-v1
recovery. Persistent multi-input recovery, GCM and rename belong to v1.0. Public
completion remains after SDK sink close; engine events are not checkpoints.
