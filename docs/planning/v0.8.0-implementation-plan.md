# v0.8.0 实现计划：有限输入的 Sample 解密

基线：v0.7.0 / 24c5ac4。本文保存已批准的实施范围；执行结果以 `docs/release-0.8.0.md` 和机器可读证据为准。

## 目标与边界

完成 roadmap 的 U03 与 U10 加密诊断：通过现有 keyed/timeline 入口处理 sample 加密输入，输出保留原 codec、sample 内容和时间信息的 clear MP4。

| 输入 | 本版支持 |
| --- | --- |
| TS SAMPLE-AES | AVC、AAC-LC |
| fMP4 SAMPLE-AES / cbcs | AVC、HEVC、AAC-LC |
| fMP4 SAMPLE-AES-CTR / cenc | AVC、HEVC、AAC-LC |
| 组合 | 单路、现有外置音频替换、范围、epoch、缺口策略、配置变化拆分 |

直接扩展现有入口，无需启用开关；真实 SDK 隔离联调属于完成门槛。
Live/EVENT、Packed AAC 正式输入、多音轨、字幕、新 checkpoint、GCM 和更名仍按后续版本交付。TS HEVC SAMPLE-AES、TS/Packed AAC SAMPLE-AES-CTR 明确拒绝。

## P0：冻结支持契约和独立测试素材

- 建立 method/container/scheme/codec/IV/output 支持表；冻结 protection box 的版本、flags、offset 基准和拒绝规则，作为 parser 与 capability 的共同验收依据。
- 延续 M0 优先级：schm/frma 确定 scheme/codec，tenc 提供默认值，sbgp/sgpd(seig) 按 sample 覆盖；senc 与 saiz/saio 同时描述数据时必须一致。
- 准备外部工具生成的 encrypted/clear fixture，记录工具版本、命令、来源、许可和 SHA-256；补充独立 CBC/CTR 向量。禁止仅以自产加密和解密互逆作为正确性证据。
- 复用现有 RustCrypto AES/CBC，增加兼容的 CTR 依赖；沿用 M0 的 cipher 0.4 依赖系列，锁定版本并复核安全公告与 WASM 构建。

退出条件：每个承诺的保护信息路径均有正例、拒绝例和独立 clear 参照。

## P1：建立正式 sample 处理通路

- 在共享内部读取层区分 clear、整资源 AES-128 和 sample 加密；sample 加密资源只做有界读取和容器结构校验，随后进入 demux，不能套用 PKCS7、整资源块对齐或 AES MAP IV 规则。
- 保留公共 ResourceSession/ClearResource 的 clear/AES-128 契约；keyed/timeline 使用新增内部 sample 资源通路，避免把仍含密文的资源公开称为 clear。
- 完善 raw sample 身份：input、track/PID、epoch、sequence、原始位置、sample 序号、timing 和 protection。解密完成后才能进行 codec 检查、关键帧判定和 NAL 归一化。
- 拆分布局约束：fMP4/AAC 保持长度和 clear 区间；TS AVC 允许去除加密层 emulation-prevention 引起的合法缩短，保留原始身份及明文 NAL 映射，禁止任意长度变化。
- Collect/Replay 按资源释放，分配前检查样本数量、描述符数量和 bytes 预算；取消覆盖 provider 等待及长解密循环。

退出条件：clear/AES-128 回归通过；异步 hook 顺序、布局变化、预算和取消有针对性测试。

## P2：实现 TS SAMPLE-AES

- 支持受保护 AVC/AAC 的 PMT 标识及相关描述符，结合 playlist method 校验，不能静默忽略加密轨道。
- AVC 按 NAL 边界处理类型 1/5、clear leader、跳块模式、CBC 重置和加密层 emulation-prevention。
- AAC 按 ADTS frame 边界保留 header、clear leader/trailer，逐 frame 重置 CBC；保护区使用无 padding 解密。
- TS 采用 KEY 显式 IV，缺省时按原始 media sequence 推导；保留 KEY 轮换和 METHOD=NONE 语义。字节规则遵循 [Apple Sample Encryption](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/HLS_Sample_Encryption/Encryption/Encryption.html)。

退出条件：完整 TS fixture 的 clear sample、时间和独立解码结果一致，覆盖短 NAL、临界长度、多个 NAL/frame 及防竞争字节。

## P3：实现 fMP4 cenc/cbcs

- 解析 encv/enca 和 sinf/frma/schm/schi/tenc，复用现有 clear codec 配置解析。
- 实现 senc、saiz/saio 和 sgpd/sbgp(seig)；支持多 traf/trun、逐 sample IV、cbcs constant IV、多 KID、轮换及 clear/encrypted 混合。
- 对 sample 数、group 映射、subsample 总长、辅助数据长度、offset 和整数运算执行检查；支持资源范围内的合法辅助数据定位，不隐式读取描述符之外的外部数据。
- cenc 实现 CTR/subsample 状态推进；cbcs 实现 pattern、CBC 链和未满块尾部保留。scheme、IV 或 KEY method 冲突直接失败，不降级为 clear。容器模型对照 [W3C CENC 描述](https://www.w3.org/TR/eme-stream-mp4/)及独立 packager fixture。
- 解密后进入现有 mux，由 clear codec 配置重建 sample entry，不复制加密 sample entry、辅助加密信息或失效的 protection metadata。

退出条件：AVC/HEVC/AAC 的两种 scheme 均通过 sample hash、独立容器解析和实际解码。

## P4：接入 session、诊断和时间轴

- keyed 与 timeline 共用 sample 通路；整段输出与范围输出采用相同解密实现。
- 将解析出的 KID 交给现有 operation-scoped KeySession，复用候选选择、请求合并、TTL、失效刷新和取消，不创建另一套 key cache。
- fMP4 IV 来自选定 protection descriptor；不以 playlist IV 替代容器 IV。clear sample 不触发无必要的 key 请求。
- timeline 扫描与输出回读同时校验资源和解密后 sample 摘要；同一密文在 key 变化后不得绕过已有 ResourceChanged 保护。缓存绑定 protection、KID、key version 和 resolve revision。
- 修正 bytes 统计：sample 加密按实际读取字节计量，不套用现有 AES-128 padding 推算；资源就绪与 sample 解密完成分别记录。
- 更新能力查询和预检；已知不支持组合尽早拒绝，媒体内才可发现的错误在对应 sample 提交前失败。

退出条件：范围、epoch、轮换、双输入、缺口和拆分组合通过，且 key 变化不会悄悄改变已验证输出。

## 公共接口与兼容

- 保留 prepare_hls_with_keys、prepare_hls_timeline 的签名与调用方式，扩展其接受范围。
- 为 AvailableKey 增加 SAMPLE-AES、SAMPLE-AES-CTR 构造方法，继续通过 with_kid 绑定 KID；KeyProvider trait 不变。
- 新增 sample profile 的 playlist 预检方法，原 resource-only 验证方法继续保持原含义。
- 新增 SampleError、非穷尽错误分类及上下文 getter，通过 keyed/timeline 错误暴露；包含 track、sample index、method/scheme、key reference/version，并保留底层 typed cause。
- 新预算配置采用私有字段和 builder，默认继承现有资源/key 上限；不扩展已有公共结构字面量或 legacy Error 穷尽枚举。
- 保留旧入口、with_audio() 替换语义、writer ownership 和 legacy checkpoint 行为。默认日志、事件和报告不包含 raw key 或未脱敏 URI。

## 验收与交付

- 算法及 parser：IV 长度、CTR 跨 subsample、CBC reset/pattern、clear 区间、NAL prefix 1/2/4 字节、多 KID、未知版本、冲突/截断 metadata、越界和计数溢出。
- 生命周期：provider unavailable/failure、同 URI 换 key、TTL/失效、单等待者与 operation 取消、迟到 Promise、慢 writer 和预算拒绝。CBC/CTR 无认证，不承诺检测所有错误 key。
- 输出组合：clear/AES-128/sample 轮换、独立音频、范围/preroll、负 CTS、epoch/reset、MAP 更新及拆分；覆盖现有各输出格式和适用的两种收尾后端。
- 运行时：Native、Node WASM、真实 Chrome 比较 clear sample、时间、报告及规范化输出 hash；分别记录 raw/replay 内存、WASM 页、JS heap 和首写延迟。
- SDK：使用已发现的 hls-downloader 工作区隔离副本，扩展现有 SourceHost/key/Promise 联调，覆盖 KID、两种 scheme、TS、范围/轮换和取消；记录 SDK revision 和上游源码摘要。
- 回归及发布准备：完成 feature 矩阵、WASM、fmt/Clippy、旧任务恢复、打包示例及发布 dry-run。生成 v0.8.0 验收文档和机器可读证据，再更新版本、README、capability 与 roadmap 状态；registry 发布和 SDK 产品上线另行执行。

实施前状态：仅完成只读调查和现有 raw sample 的 12 项基线测试，尚未实施 v0.8.0。
